# Claude по подписке (claude CLI)

Третья нейросеть рядом с Gemini и Claude API (19.10.2026). Это официальный Claude Code CLI (`claude -p`) в headless-режиме, со своей подпиской Pro/Max: ключ API не нужен. Работает во всех четырёх задачах:
- W2 — оценка вакансий;
- W5 — письма;
- W11 — профиль из PDF;
- W13 — рекомендации по резюме.

Включается в боте: ⚙️ → 🤖 Нейросеть → «Модель: Claude по подписке».

Если кончился лимит подписки или слетел вход, этот вызов делает Gemini — тем же запросом, что ушёл бы при `llm.provider = gemini`. В письме и в сообщении о сборе тогда появляется строка.

## Как устроено

```
W2/W5/W11/W13: Build ─▶ Switch «Provider» ─┬ claude     ─▶ HTTP «Claude» (Claude API)  ─┐
                                            ├ claude-cli ─▶ HTTP «Claude CLI» ───────────┼▶ Parse
                                            └ иначе      ─▶ HTTP «Gemini» ────────────────┘
HTTP «Claude CLI» ─▶ http://claude-cli:3000/v1/messages   (сеть compose llm: её видит только n8n)

claude-cli: дорожка score (W2, по одному) │ дорожка text (W5/W11/W13, до двух)
   ─▶ предохранитель (лимит, вход, бюджет оценок) ─▶ claude -p … (stream-json)
        ├ ответ ─▶ 200 в форме Claude API (provider: claude-cli, model — какая ответила на самом деле)
        └ сбой  ─▶ Gemini тем телом, что прислал n8n ─▶ ответ Gemini (provider: gemini, fallback: { reason, until, note })
```

**Сервис `claude-cli/`.** Node без зависимостей и официальный бинарник `@anthropic-ai/claude-code`. Версия закреплена (`CLAUDE_CODE_VERSION`, сейчас 2.1.303). Контейнер поднимает деплой, если в `.env` есть `CLAUDE_CODE_OAUTH_TOKEN` (профиль compose `claude`). Пересборка и перезапуск — на каждом деплое: состояния у сервиса нет, образ в кэше.

**Запрос** — тело Claude API (Build-ноды его уже строят) плюс поля:

| Поле | Смысл |
|---|---|
| `task` | `score` (W2) или `text` (W5, W11, W13): дорожка, бюджет, таймаут |
| `effort` | `low` — у моделей 5.5 мышление не выключается, это минимум |
| `deadline_ms` | сколько ждёт n8n: 170 с, у W13 — 290 с (правка резюме до 3–4 минут) |
| `fallback` | `{ model, body }` — готовый запрос Gemini |

`temperature` и `max_tokens` CLI не задаёт.

**Ответ.**
- CLI ответил — форма Claude API, а `model` — та модель, что ответила на самом деле (`modelUsage`): CLI меняет её на флаге безопасности. Эта модель уходит в `llm_model` (W2) и `letter_model` (W5).
- Сработал запасной путь — сырой ответ Gemini с полями `provider: 'gemini'` и `fallback`.
- Перехода нет (нет ключа Gemini) — ошибка в форме Claude API: 429 лимит, 401 вход, 503 занят или сбой, 504 таймаут, 502 ответ не по схеме. Текст ошибки начинается с «Claude по подписке: …».

**Как запускается CLI.** Один процесс на запрос:

```
claude -p --output-format stream-json --verbose --model <ID> --effort low
  --system-prompt-file <tmpfs> --json-schema '<схема>' --tools "" --strict-mcp-config
  --disable-slash-commands --no-session-persistence --permission-prompts none --max-turns 4
```

- Задание идёт через stdin, рабочая папка — пустая `/work`, у каждого вызова свой `CLAUDE_CONFIG_DIR` в tmpfs.
- Процесс получает только белый список env. `ANTHROPIC_API_KEY` важнее OAuth-токена, поэтому его нет; ключа Gemini тоже нет.
- `--tools ""` оставляет одно: инструмент StructuredOutput, через который CLI отдаёт ответ по схеме (разведка 19.10.2026). Команды, файлы, MCP и хуки недоступны.

**Сбои распознаются по событиям stream-json**, а не по тексту:
- `system/api_retry` с `error` = `rate_limit` / `authentication_failed` / `billing_error` → процесс убивается сразу, без повторов CLI;
- `rate_limit_event` → загрузка окон подписки (5 часов, неделя) и время сброса;
- итог `result` → `structured_output`, `usage`, `modelUsage`, `api_error_status`.

Текст ошибки — запасной путь, его форма не документирована: «You've hit your session limit · resets 6:10pm», «…Sonnet limit · resets Mon 12:00am». Время сброса читается по поясу контейнера (`TZ` = `USER_TZ`). Неизвестная форма → полчаса без CLI.

**Предохранитель** (состояние в памяти; перезапуск сервиса и `reset` его сбрасывают):
- лимит подписки — до сброса. Лимит одной линейки («Sonnet limit») не останавливает другие: оценка на Haiku продолжается;
- вход слетел — 30 минут без CLI;
- бюджет оценок: W2 не берёт подписку, если окно 5 часов или недели занято на `CLAUDE_CLI_SCORE_MAX_UTIL` (по умолчанию 0.8) и больше. Лимит общий с твоей работой в Claude Code — она важнее сбора. Письма и резюме идут до настоящего лимита.

Пока действует предохранитель, вызов сразу уходит в Gemini, `claude` не запускается.

**Очередь.** n8n не ждёт ответа перед следующим запросом пачки: `batchInterval` разносит только старты, а дождаться `Promise.allSettled` — это видно по исходникам 2.42.3. Поэтому очередь живёт в сервисе:
- дорожка оценок — один запуск за раз, дорожка текстов — до двух, так что пачка оценок не задерживает письмо;
- n8n закрыл соединение (таймаут ноды) — задача снимается, процесс убивается;
- не успевает к `deadline_ms` с запасом 35 с на Gemini — сразу Gemini;
- у W2 ноды «Claude CLI» стартуют раз в 6 с — это примерно время ответа Haiku.

## Включить

1. **Токен.** В своём терминале, на любом компьютере с Claude Code: `claude setup-token`. Откроется вход в браузере, в терминале появится токен `sk-ant-oat01-…`. Он живёт год и умеет только запросы к модели. Claude Code нет — тот же CLI из контейнера: `docker compose --profile claude run --rm claude-cli claude setup-token`. Ссылку открой в браузере, код из браузера вставь в терминал.
2. **`.env`:** строка `CLAUDE_CODE_OAUTH_TOKEN=sk-ant-oat01-…`. Ключ Gemini (`GEMINI_API_KEY`) лучше оставить: он — запасной путь.
3. **Деплой** (`scripts/deploy.sh`, у чужих установок — `node scripts/install.mjs`): соберёт и поднимет `claude-cli`.
4. **Проверка:** `docker compose exec claude-cli node src/ask.mjs check` → «✓ Claude по подписке отвечает: claude-haiku-5-5, 4 с».
5. **Бот:** ⚙️ → 🤖 Нейросеть → «Модель: … ▸» до «Claude по подписке».

Мастер установки делает шаги 1–4 сам: шаг «Нейросеть», вопрос «Подключить Claude по подписке?». После деплоя он спрашивает, сделать ли Claude основной нейросетью; если Gemini нет — ставит без вопроса.

## Модели

Модели выбираются в ⚙️ → 🤖, кнопки появляются при Claude по подписке:

| Настройка | По умолчанию | По кругу | Где |
|---|---|---|---|
| `llm.cli_score` | Haiku 5.5 (`claude-haiku-5-5`) | Haiku 5.5 → Sonnet 5.5 → Opus 5.5 | W2, оценка |
| `llm.cli_text` | Sonnet 5.5 (`claude-sonnet-5-5`) | Sonnet 5.5 → Opus 5.5 → Haiku 5.5 | W5 письма, W11 профиль, W13 резюме |

- Модели задаются только полными ID, их же принимает сервис (`claude-cli/src/models.mjs`). Алиасы `haiku`, `sonnet` и `default` со временем указывают на другие модели, а теневому режиму нужна точная.
- **Fable нет:** на Pro `claude -p` с Fable молча списывает платные кредиты.
- Под письмом всегда мелко видно, кто его написал: «✉️ Письмо · … · *Sonnet 5.5*» (колонка `letter_model`).

Разведка 19.10.2026 на выдуманном профиле:
- оценка на Haiku 5.5 — 4 с, из них 2 с на запуск CLI, мышления 0 токенов;
- письмо на Sonnet 5.5 — 17 с, около 1500 токенов мышления даже при `low`. Письмо — по фактам, без тире.

## Лимит, вход и запасной Gemini

| Что случилось | Что видно |
|---|---|
| Лимит подписки, окно занято (только оценки), очередь или сбой — вызов сделал Gemini | W2: тихая строка в сообщении о сборе «🤖 Claude по подписке: лимит подписки до 15:00. Оценил Gemini: N.» · W5: строка под письмом «⚠️ Claude по подписке: … — письмо написал Gemini», в шапке — Gemini |
| Лимит, а ключа Gemini нет | W2: тихо «⏸ … Не оценено N — оценю после сброса» (строки вернутся в очередь) · W5, W11, W13: «не получилось: Claude по подписке: лимит … до 15:00» |
| Вход слетел (токен истёк или отозван), нет токена | W2: тревога со звуком, не чаще раза в сутки (static data `cliAuthDay`), с починкой |
| Сервис не отвечает (контейнер не запущен) | «сеть: сервис Claude по подписке (claude-cli) не отвечает» — временный сбой, громко после 3 запусков подряд |

**Вход слетел — починка:**
1. `claude setup-token`.
2. Новая строка `CLAUDE_CODE_OAUTH_TOKEN` в `.env`.
3. `scripts/deploy.sh` — перезапуск сервиса сбросит предохранитель.

## Правила Anthropic и приватность

Проверено 19.10.2026: [legal and compliance](https://code.claude.com/docs/en/legal-and-compliance), [Agent SDK и подписка](https://support.claude.com/en/articles/15036540).

- Своя подписка и неизменённый официальный CLI — можно. Запросы других людей через Pro/Max — нельзя: будущий платный сервис — только на API-ключе.
- На Pro `claude -p` тратит **тот же лимит**, что claude.ai и Claude Code. Отдельный ежемесячный кредит для `-p` — только у Max и Team (с 07.10.2026).
- Из России Claude недоступен: важно, где находится человек, а не сервер.
- На подписке переписка и сессии Claude Code идут в обучение, если в claude.ai включено «Help improve Claude». Сюда относятся и резюме, и вакансии. Предупреждение бота при первом запуске это называет.

## Безопасность

- Токен лежит только в `.env` (права 600) и в env контейнера `claude-cli`. Ключ Gemini там тоже есть — для запасного пути.
- Порта на хосте нет. Сервис в отдельной сети compose `llm`, её видят только он и n8n. Chromium робота (сеть `default`) до него не достаёт.
- `POST` принимается только с `Content-Type: application/json`: браузер не отправит такой запрос с чужой страницы без CORS. Тело — до 2 МБ: промпт идёт дважды, для Claude и Gemini.
- У CLI нет инструментов, MCP, slash-команд и истории сессий; env — белый список. В журнал (`docker compose logs claude-cli`) идут задача, модель, исход, время, токены и загрузка окон. Тексты промптов не пишутся.

## Проверка и отладка

Команды запускаются внутри контейнера: `docker compose exec claude-cli node src/ask.mjs <команда>`.

| Команда | Что делает |
|---|---|
| `state` | предохранитель, загрузка окон подписки, дорожки, счётчики с запуска |
| `check` | один короткий настоящий вызов (Haiku 5.5, без запасного Gemini) |
| `simulate limit` | следующий вызов — как лимит подписки: предохранитель на 10 мин, вызовы уходят в Gemini |
| `simulate auth` | то же для сбоя входа: 30 мин; сводка W2 даёт тревогу |
| `simulate down timeout bad` | разовые сбои без предохранителя |
| `reset` | снять предохранитель и симуляцию |

**Тесты:**
- `cd claude-cli && npm test` — разбор stream-json на фикстурах разведки, предохранитель, дорожки, запуск CLI (процесс подменён), обработчик, HTTP-слой.
- `node --test scripts/test-llm.mjs`:
  - golden-тела W2, W5 и `llm.js` для Gemini и Claude API — байт в байт как до Claude по подписке, обновлять только осознанно: `UPDATE_GOLDEN=1`;
  - тела claude-cli;
  - разбор ответов сервиса.

## Обновление CLI

Новая версия, особенно перед сменой модели, — сначала разведка на Mac:
1. Запустить `claude -p --safe-mode` в пустой папке на промптах W2 и W5. Промпты собрать `runNode` из `scripts/lib/sandbox.mjs` на выдуманном профиле, как в `scripts/test-llm.mjs`.
2. Проверить:
   - `structured_output` при `--tools ""`;
   - события stream-json;
   - нет ли `unrecognized_model` в stderr: 2.1.292 не знал Haiku 5.5, 2.1.303 знает;
   - не стал ли `--bare` поведением `-p` по умолчанию: документация это обещает, а `--bare` не читает OAuth-токен.
3. Если всё в порядке — новая версия в `CLAUDE_CODE_VERSION` (`.env` или `claude-cli/Dockerfile`), `cd claude-cli && npm test` и деплой.

## Ограничения

- Температуру и seed CLI не задаёт. Оценка повторяется хуже, чем у Gemini с temperature 0, поэтому теневой режим делим по `llm_model`.
- К системному промпту CLI добавляет свою строку личности (Claude Code). На письмах разведки это не мешало.
- Форма текста лимита не документирована: неизвестная форма даёт +30 минут без CLI. Это лишний переход на Gemini, но не потеря.
- Модели после 5.5 могут потребовать новую версию CLI — см. «Обновление CLI».

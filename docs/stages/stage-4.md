# Этап 4 — сопроводительное письмо и отклик (полуавтомат A)

**Цель:** по ✅ на карточке нейросеть пишет сопроводительное письмо. Пользователь читает его, копирует одним нажатием, открывает форму отклика на hh и отправляет сам. Без робота и без риска для аккаунта.

Решения пользователя (07.10.2026):

| Вопрос | Решение |
|---|---|
| Когда письмо | сразу по ✅; отклик отправляется только после того, как пользователь прочитал письмо |
| Отправка | сам, в два нажатия: скопировать письмо → «📝 Отклик на hh» → вставить → отправить → «📨 Отправил» |
| Нейросеть | Gemini Flash-Lite, бесплатно (Flash на бесплатном ключе отвечает 503) |
| Язык, длина | всегда по-русски; 14.10.2026 — три абзаца, 600–900 знаков: главная задача вакансии и что делал под неё → вторая задача → одна фраза-концовка (было 400–700 знаков по образцам `docs/letter-example.md` — письма выходили короткими и с одними и теми же фактами, образцы выключены) |
| Тон | делово, без канцелярита; 07.10.2026 — «письмо не должно звучать как нейросеть»: стиль «А» (конкретные дела, простые глаголы), без тире и штампов |
| Компании | по имени (Руб Икс, WillSkill, Revoluterra); бэкенд и инфраструктура — «работал в пет-проектах» |
| «Готов погрузиться в …» | только для навыков, которых нет в профиле; код размечает навыки вакансии по профилю до запроса к модели |
| Конец письма | «Для быстрой связи тг: @freshraveprince» + «Никита» |
| Не писать | где живёт, зарплату, когда готов выйти |
| Про AI-инструменты | только если вакансия про AI |
| Правки | ответом на письмо («короче», «добавь про дизайн-систему») или «🔄 Переписать». 14.10.2026: пожелание главнее правил о стиле, «я знаю PHP» — факт; пожелания вакансии идут во все следующие варианты; «🔄» — другая подача (другое начало, детали и слова; лучший факт может остаться) |
| После «📨 Отправил» | все кнопки убираются, остаются «↩️ Отменить» (возвращает прежние кнопки) и «📋 К вакансиям» (07.10.2026: список меню там, где был) |
| Передумал после ✅ | 14.10.2026: «↩️ Отменить отклик» под письмом — вакансия снова в «⏳ Ждут решения». Письмо удаляется и забывается (✅ снова — новое письмо), решение и «Почему?» сбрасываются, 3 дня до «⌛ устарела» считаются заново. После «📨 Отправил» этой кнопки нет — сначала «↩️ Отменить» |
| Старое письмо | 07.10.2026: когда пришло новое (🔄 или правка), прежнее удаляется; при правке — и ответ с пожеланием (оно видно в новом письме) |
| «Чем интересна вакансия» | только при реальном пересечении с опытом, просто и без лести; иначе фразы нет |
| Ссылки | обе: форма отклика (браузер) и страница вакансии (на телефоне откроет приложение hh) |

Профиль для писем и оценки — `docs/resume.md` + раздел «Дополнительно» (fullstack в своих и фриланс-проектах, Python/FastAPI, AI-assisted development — подтверждено пользователем 07.10.2026).

## Как устроено

```
W3 Telegram  ✅ на карточке (письма ещё нет) ─┐
             «🔄 Переписать» под письмом ─────┼→ Letter job → Write letter (Execute Workflow, без ожидания)
             ответ (reply) на письмо ─────────┘
             «📨 Отправил» → Sent row → Apply sent → Save sent: status = applied, applied_at
                → у письма остаётся только «↩️ Отменить», у карточки кнопок нет, строка «📨 Отклик отправлен»
             «↩️ Отменить» → status = approved, applied_at пусто → письму возвращаются все кнопки, карточке — «↩️ Изменить»
             «↩️ Отменить отклик» → Sent row → Apply cancel → Answer cancel (тост) → Save cancel: status = waiting,
                my_decision, my_reason, letter пусто, tg_letter_id = tg_ask_id = 0, card_at = сейчас
                → карточке — кнопки выбора → письмо без кнопок → удалить письмо и «Почему?» без ответа
                (отказ без записи: робот в работе, письмо ещё пишется, отклик отправлен, вакансия закрыта)

W5 Letter    Called by W3 | Manual → Approved (✅ без письма)
             → Jobs → Vacancy → Settings (профиль, стиль, образцы) → Build letter → Gemini | Claude | Claude CLI → Parse letter
             → Format letter → Send letter (ответом на карточку, кнопки) → Letter sent → Save letter
             → Old letters → Delete old letter (прежнее письмо, ответ с пожеланием)
```

- Код: `n8n/w5-letter/*.js`, `n8n/w3-telegram/{letter-job,reply-kind,apply-sent,apply-cancel,cancel-ids}.js`.
- Колонки: `letter`, `tg_letter_id` (на это сообщение отвечают с правкой), `letter_notes` (пожелания через « | », без повторов: с 14.10.2026 идут во все следующие варианты письма вакансии и остаются материалом для улучшения промпта), `applied_at`.
- Задание нейросети (`build-letter.js`, 14.10.2026):
  - новое письмо и «🔄» — схема ответа `needs` → `matches` → `first`, `second`, `closing`: сначала разбор вакансии (главные задачи и факт профиля под каждую), потом три абзаца; `parse-letter.js` склеивает их и ставит «Здравствуйте!»;
  - «🔄» — прошлое письмо целиком не показываем (Flash-Lite его копировал), только его первое предложение и откуда брались факты; зачин — случайный из двух других, у Gemini — случайный `seed`;
  - правка — текущее письмо, прежние пожелания и `<wish>`: пожелание главное, что кандидат пишет о себе — факт, остальные факты — только из профиля;
  - навык из пожелания («я знаю PHP») — отдельная строка разметки «кандидат пишет о них сам», в задании — «скажи отдельным предложением, без названия компании»; `parse-letter.js` убирает «готов погрузиться в …» с ним (`said` в выходе «Build letter»).
- Нейросеть повторилась (`parse-letter.js`, `same`): правка вернула то же письмо или «🔄» почти как прошлое (≥ 0.8 общих троек слов) — письмо всё равно уходит, в нём строка ⚠️. Не ошибка «⚠️ Письмо не получилось»: на неё правкой не ответить (W3 ищет письмо по `tg_letter_id`).
- Новое письмо (🔄 или правка) приходит новым сообщением, после записи W5 удаляет прежнее письмо (`tg_letter_id` до записи) и то, что передал W3 (`replace`: сообщение, где нажали «🔄», или письмо и ответ с пожеланием). Новое не получилось — ничего не удаляется. Сообщения старше 48 ч Telegram удалить не даёт — остаются.
- После «📨 Отправил» / «↩️ Отменить» / «↩️ Отменить отклик» W3 обновляет панель меню (W7), если на ней открыта эта вакансия.
- «↩️ Отменить отклик»: письмо сначала правится без кнопок, потом удаляется — старше 48 ч Telegram удалить не даёт, остаётся «↩️ Отклик отменён» без кнопок. Удалённый «Почему?» мог спрятать кнопки меню — вернутся со следующим сообщением о сборе или по `/menu`.
- Нейросеть не ответила → сообщение «⚠️ Письмо не получилось…» с кнопкой «🔄 Переписать».

```
✉️ Письмо · Senior React разработчик · Loyalty Labs
┌──────────────────────────────┐
│ Здравствуйте!                │   ← блок <pre>: нажатие копирует текст
│ …                            │
│ Для быстрой связи тг: @…     │
│ Никита                       │
└──────────────────────────────┘
Нажми на письмо — скопируется. Поправить — ответь на это сообщение.
Факт о себе для всех писем — ⚙️ → 👤 Профиль → ➕ Дополнительно к резюме.   ← только под письмом с правкой
[📝 Отклик на hh] [🔗 Вакансия]
[🔄 Переписать]   [📨 Отправил]
[↩️ Отменить отклик]
```

Заголовок: «✉️ Письмо» (новое), «🔄 Новый вариант письма», «✏️ Письмо с правкой» (+ строка «Пожелание: «…»»). Нейросеть
повторилась — под заголовком «⚠️ Нейросеть не поменяла письмо. Напиши пожелание иначе…» (правка) или «⚠️ Вариант почти
как прошлый — нажми «🔄 Переписать» ещё раз».

## Проверка

```bash
# выходы нод «Jobs», «Vacancy», «Settings» из запуска W5 — JSON вне репозитория (там резюме)
node scripts/run-code-node.mjs n8n/w5-letter/build-letter.js <jobs.json> --ref 'Jobs=@<jobs.json>' \
  --ref 'Vacancy=@<rows.json>' --ref 'Settings=@<settings.json>' --out <built.json>
# ответ нейросети: [{ "statusCode": 200, "data": "<тело ответа Gemini>" }]
node scripts/run-code-node.mjs n8n/w5-letter/parse-letter.js <response.json> --ref 'Build letter=@<built.json>' \
  --ref 'Vacancy=@<rows.json>' --ref 'Settings=@<settings.json>'
node scripts/n8n-api.mjs run jobHunterW5Lettr     # письма ко всем ✅ без письма
```

## Готово, когда

- по ✅ приходит письмо, правки и «🔄» работают, «📨 Отправил» отмечает отклик;
- письма не приходится переписывать вручную в большинстве случаев (смотрим `letter_notes`).

# Этап 6 — робот-отклик на hh.ru (🚀) + статусы откликов и чаты HR

**Цель:** нажатие 🚀 под письмом → робот сам откликается на hh с этим письмом и отчитывается в том же сообщении. Плюс
(робот всё равно вошёл в hh): статусы откликов (просмотр / приглашение / отказ) и сообщения HR в Telegram.

**Почему так.** Отклик вручную (этап 4) — рутина: 36 откликов за 4 дня, до 20 в день. API соискателей hh закрыт с
15.12.2025 → только браузер (путь C, CLAUDE.md §4; автоматизация против правил hh — риск ограничений аккаунта принят).
Теневой режим (10.10.2026): 60 пар оценок, совпало 25 (42%), нейросеть поймала 12 из 39 откликов пользователя →
робот **сам не решает**, только по кнопке. Разбор теневого режима — отдельно, после робота.

## Принципы

1. **n8n — оркестратор и единственный источник бизнес-состояния** (очередь, статусы, лимит, уведомления).
   **applier — исполнитель**: знает только браузер и hh, хранит то, что живёт в браузере (сессия, открытая капча), и
   предохранители, которые держат даже при ошибке в n8n.
2. **Один писатель:** переходы очереди (`apply_state`) делает только W9; W3 и W7 передают команды.
3. **Безопасно по умолчанию:** `APPLY_LIVE=0`, `apply.enabled=false`; необратимое — только через `act()`; одно действие за раз.
4. **hh — истина:** «уже откликались» проверяется перед кликом → любой повтор безопасен.
5. **Сеть важнее DOM:** исход — по ответам API, которые делает сам интерфейс hh; знание hh — в `applier/src/hh/`.
6. **Непонятно → человеку:** неясный исход возвращает вакансию в ✅ с пометкой; ручной 📝 работает всегда.

## Как устроено

```
Telegram ⇄ ngrok ⇄ W3 (Route) ──🚀 ⛔ ▶️ /go, ответ на капчу──▶ W9 Robot ◀── Schedule каждую минуту
W5 Letter: письмо с 🚀, если можно                              ▲   └── вызывает себя после успеха
W7 ⚙️ 🚀 Робот ──(выключили → очередь назад; сняли паузу → tick)─┘
W8 Clock → Due → W1;  W8 → Inbox due → W10 Inbox ──(блок)──▶ W9 alert
W9 / W10 / W7 / W6 ──HTTP, X-Applier-Token──▶ applier:3000 (job-hunter-applier)
                                             Xvfb + fluxbox + x11vnc → 127.0.0.1:5901 («Общий экран»)
                                             Chromium с окном, постоянный профиль → hh.ru (домашний IP)
CLI scripts/applier.mjs ──▶ 127.0.0.1:5682
```

### Робот `applier/` (Node.js, Playwright)

| Слой | Файлы | Что делает |
|---|---|---|
| http | `src/server.mjs` | адреса, токен `X-Applier-Token`, замок (одно действие за раз: занято → 409, блок → 423), фоновые задания, обслуживание, мягкая остановка |
| сессия | `src/browser.mjs` | Chromium с окном, профиль `/data/profile`; бэкап `storageState` после входа и раз в час (сессионные cookie Chromium не хранит) + восстановление; перезапуск раз в сутки в 05:00 по Таиланду; сетевой предохранитель; скриншоты JPEG |
| состояние | `src/store.mjs` | блок (капча, вход, лимит hh, сбои) и счётчики «дня» — `/data/state.json`; последний результат по вакансии — в памяти на сутки |
| hh | `src/hh/selectors.mjs`, `src/hh/state.mjs` | все `data-qa` и тексты-маркеры (дословно из переводов hh); чистые функции: InitialState, факты вакансии, прогноз, группы исходов |
| сценарии | `src/flows/apply.mjs`, `recon.mjs`, `record.mjs`, `dom.mjs` | отклик (в 6.0 — до точки сухого прогона), разведка, запись, общие действия со страницей |

**Предохранители.** `APPLY_LIVE=0` — робот не нажимает «Откликнуться» вообще (6.0 — всегда). Сетевой фильтр рвёт не-GET
запросы к `/applicant/…`, `/shards/applicant/…`, `chatik.hh.ru` и переход на страницу отклика — выключается только на
время записи (откликается человек) и живого отклика (6.1b). Потолок `APPLIER_DAILY_CAP=40` в «день» робота.

**Окружение.** Сервис `applier` в `docker-compose.yml` (профиль `applier`): `init`, `shm_size: 1gb`, `mem_limit: 2g`,
`stop_grace_period: 200s`; порты `127.0.0.1:5901` (VNC; 5900 — «Общий экран» самого Mac) и `127.0.0.1:5682` (API для
CLI; 5681 занят брокером второго CLI n8n); том `applier_data:/data`; `./fixtures/applier:/data/recon` (не в git).
`.env`: `APPLIER_TOKEN`, `VNC_PASSWORD` (≤ 8 символов — ограничение VNC), `APPLY_LIVE`, `APPLIER_FAKE`,
`APPLIER_DAILY_CAP`, `HH_RESUME_TITLE`. Профиль браузера и сессия hh — только в томе; журналы — без текстов писем,
cookie и токена; разведка вырезает токены и данные аккаунта (`state.json`), а `page.html` хранит как есть — в
`fixtures/` (не в git).

## 6.0: запуск, вход, разведка, запись

```bash
# 1. В .env: APPLIER_TOKEN (openssl rand -hex 24), VNC_PASSWORD (≤ 8 символов), APPLY_LIVE=0 — см. .env.example
scripts/deploy.sh --applier                      # профиль applier в COMPOSE_PROFILES, сборка и запуск робота
node scripts/applier.mjs status                  # браузер up, не вошли

# 2. Вход: откроется «Общий экран» (vnc://localhost:5901, пароль — VNC_PASSWORD) со страницей входа hh.
#    Войти по телефону и коду; закрыть плашки «Ваш регион — …?» и cookie. Команда ждёт входа до 10 минут
node scripts/applier.mjs login
docker compose restart applier && node scripts/applier.mjs status   # вход пережил перезапуск

# 3. Разведка: ~10 вакансий разных типов, 20–40 с между ними, без кликов → fixtures/applier/recon-…
node scripts/applier.mjs recon <id> <id> …
node scripts/applier.mjs recon --inbox           # «Отклики» и чаты; непрочитанные до и после должны совпасть

# 4. Запись: пользователь сам откликается в окне робота на 2–3 вакансии из ✅, робот снимает каждый экран и ответы hh
node scripts/applier.mjs record start
node scripts/applier.mjs record stop

# 5. Сухой прогон: до кнопки, без клика
node scripts/applier.mjs apply <id> --letter-file <файл>
```

Если робот упёрся в капчу или вышел из hh — блок (`status` покажет); после «Общего экрана» —
`node scripts/applier.mjs resume`.

### Разведка: что выяснили (10.10.2026)

**Вход.** Вошли через «Общий экран»; `hhtoken` живёт ~13 месяцев (до 11.2027), `hhrole`, `crypted_id`, `_xsrf` —
сессионные: робот восстанавливает их из бэкапа `storageState`, вход пережил `docker compose restart`.

**Прогноз без клика — `GET /applicant/vacancy_response/popup?vacancyId=N`** (его зовёт сам интерфейс hh):

| `type` | Что сделает hh по «Откликнуться» | Что в ответе |
|---|---|---|
| `modal` | окно с полем письма, отправка — кнопкой в окне | `responsePopup {type: normal}`, `responseStatus`, `relocationWarning`, `lastResponseLetter`, `lastResponseResumeHash` |
| `quickResponse` | отклик уходит сразу, письмо — «Приложить сопроводительное» после | `body {resume_hash, vacancy_id, letterRequired, letterMaxLength, responseStatus}` |
| `test-required` | переход на страницу вопросов работодателя | `redirect_uri`, `relocationWarning` |
| `alreadyApplied` | отклик уже есть | — |
| `need-login` | не вошли | `redirect_uri` на вход |

`relocationWarning.show` — покажет ли hh «Вы откликаетесь на вакансию в другой стране» (на Израиле и Москве — нет).
Без входа `popup` звать нельзя: hh, похоже, запоминает «откликнуться после входа» — у вакансии с тестом, которую
открывали до входа, после входа страница сама перешла на `/applicant/vacancy_response` (GET, ничего не отправляет;
предохранитель теперь такие переходы только пишет в журнал, рвёт лишь не-GET).

**Страница вакансии вошедшему:** `applicantVacancyResponseStatuses[id]` — `alreadyApplied`, `responseImpossible`,
`usedResumeIds` / `unusedResumeIds` (одно резюме), `test {hasTests, testId, required}`, `resumes`.
Из 5 вакансий в ✅ три оказались уже отправленными вручную без «📨 Отправил» — тот самый случай автоотметки 6.2.

**«Отклики»** (`/applicant/negotiations`, InitialState `applicantNegotiations`): по 20 на странице (136 всего, 7 страниц),
`applicantNegotiationsCounters` (всего: ждут ответа 77, отказ 49, собеседование 10). У отклика: `vacancyId`, `chatId`,
`lastState` (RESPONSE / DISCARD / INTERVIEW …), `viewedByOpponent`, `hasResponseLetter`, `hasNewMessages`, `lastModified`.
У 3 из 20 последних откликов `hasResponseLetter=false` — письмо до hh не дошло.

**Чаты** — `GET chatik.hh.ru/chatik/api/chats` с cookie браузера (HTTP 200): `chats.items[]` — `id`, `unreadCount`,
`resources {NEGOTIATION_TOPIC, VACANCY, RESUME}`, `currentParticipantId`, `lastMessage {id, text (полный), creationTime,
participantId, participantDisplay {name, isBot}}`; `chatsDisplayInfo[chatId] = {title (вакансия), subtitle (компания)}`;
курсор `nextFrom`. Автоответ работодателя отличим по `isBot`. Счётчик непрочитанных до и после чтения не изменился.

### Запись: как hh отправляет отклик (10.10.2026, 2 отклика пользователя в окне робота)

**Окно с письмом** (`modal`, вакансия с обязательным письмом): «Откликнуться» → `GET popup?vacancyId=N&isTest=…` →
окно (`vacancy-response-popup-form-letter-input`, `vacancy-response-submit-popup`) → письмо → «Откликнуться» в окне →
`POST /applicant/vacancy_response/popup` (multipart: `_xsrf`, `vacancy_id`, `resume_hash`, `ignore_postponed=true`,
`incomplete=false`, `mark_applicant_visible_in_vacancy_country=false`, `country_ids=[]`, `letter`, `lux=true`,
`withoutTest=no`) → ответ `{success: "true", topic_id, chat_id, responseStatus, …}` → вместо кнопки — «Чат»
(`vacancy-response-link-view-topic`). **Подтверждение отклика для робота — `success: "true"` в этом ответе.**

**В один клик** (`quickResponse`): клик по «Откликнуться» — это GET `/applicant/vacancy_response?vacancyId=…` →
**302 на `/vacancy/N?forceQuickResponse=true`** → страница сама шлёт `POST …/popup` (тот же ответ, письма нет, в форме
есть пустое `captchaText`) → «Резюме доставлено», «Приложить сопроводительное письмо», «Чат». Дальше «Приложить…» →
окно «Сопроводительное письмо» (`…letter-input`, «Отправить» `vacancy-response-letter-submit`) →
`POST /applicant/vacancy_response/edit_ajax` (`_xsrf`, `text`) — **у Nitka вернул 403**, письмо не прицепилось.
Письмо дошло через чат: «Чат» → iframe chatik → `POST chatik.hh.ru/chatik/api/save {text}` → `{text, messageId}`.
Значит, запасной путь «письмо в чат» нужен на практике. Открытие чата шлёт `POST chatik/api/notify_chat_opened` —
поэтому входящие (6.2) читаем без открытия чатов.

**Предохранитель:** в сухом прогоне и разведке рвём не-GET к `/applicant/…`, `/shards/applicant/…`, chatik и переход
на `?forceQuickResponse=true` (страница сама отправила бы отклик).

**Прочее.** `navigator.webdriver = true`; за 10 вакансий и «Отклики» капчи не было. У нового профиля всплывали
«Ваш регион — Москва?» и баннер cookie — закрыты при входе.

## 6.1a: W9 Robot — как устроено

```
🚀 (l:<id>:robot) → W3 «Robot?» → W9 enqueue: Row → Plan → Enqueue (Update: id + status=approved + apply_state пусто → queued)
   → Done → View (письмо «⏳ Робот откликается…» [⛔]) · Answer (тост) · Tick? → очередь
Очередь (tick: расписание раз в минуту, после 🚀, ▶️, капчи, смены ⚙️, сам W9 после успеха):
   Queue (apply_state не пуст) → Today (живые отклики робота с 09:00 по Таиланду) → Health (GET /health) → Gate
   Gate → Heal (applying > 6 мин → queued; не ✅ → снять) · Resolved (блок снят → «✅ снова в работе») ·
          Notice (капча — фото с ForceReply; вход / «Я не робот» / 3 сбоя / стоп hh — тревога с [▶️]; не отвечает, лимит — текст)
          · Gate views (нажали 🚀, а робот ждёт — «⏸ Робот ждёт: …») · Next → Claim (queued → applying) → Apply (POST /apply)
          → Result → View · Save result · Card: done · Shot (скриншот при сбое и сухом прогоне) · Panel sync (W7) · More → W9
⛔ (l:<id>:stop) → W9 stop: Unqueue (Update: id + apply_state=queued → '') → письмо с кнопками
▶️ (rb:go) / /go → W9 resume: POST /resume → тост или сообщение → очередь
Ответ на фото капчи → W3 → W9 captcha: POST /captcha → фото и ответ удаляются → «✅ Капча принята» → очередь | новое фото
⚙️ → 🚀 Робот: выключили → W9 dequeue (очередь назад в ✅, письма без 🚀); сняли паузу, сменили лимит → W9 tick
```

- **Очередь — колонка `apply_state`**, статус вакансии остаётся `approved` до отклика. Все переходы — Update с условием:
  двойное нажатие, ⛔ во время отправки и два параллельных W9 ничего не ломают (Update отдаёт только обновлённые строки).
- **Static data W9:** `alertedSince` (одна тревога на блок), `alertMessageId` (её поправить, когда блок снимут),
  `captchaPromptId`, `downDay` / `limitDay` (такие сообщения — раз в «день» робота). Импорт workflow её не стирает.
- **Тихие часы:** тревога, которую нашёл тик расписания (не нажатие), в 23–09 по Таиланду — без звука.
- **Письмо с 🚀** — W5 `Send letter: robot`, если `apply.enabled` и вакансия подходит (✅, письмо есть, нет теста, не на сайте
  работодателя); «↩️ Отменить» под «📨 Отправил» возвращает 🚀 так же. Старые письма — без 🚀 (решение пользователя).
- **Защиты W3:** пока вакансия в очереди, кнопки карточки, «📨 Отправил» и правка письма ответом не действуют.
- **Фейковый робот** (`APPLIER_FAKE=1` в `.env` → `scripts/deploy.sh --applier`): `node scripts/applier.mjs fake applied
  captcha login …` — следующие исходы по порядку (список — `fake help`); `/captcha ok` решает «капчу», ▶️ снимает блок.

## Риски

| Риск | Защита |
|---|---|
| hh ограничит аккаунт | каждый отклик — по 🚀; ≤ 25 в день + потолок 40; браузер с окном, один профиль, домашний IP, без подмен; паузы внутри страницы; одно действие за раз; капча — человеку; неизвестный экран → `error` + скриншот; 3 сбоя, лимит hh, тексты-стопы → блок и тревога; выключатели: ⏸, `apply.enabled`, `APPLY_LIVE=0`, `docker compose stop applier` |
| Необратимый отклик в один клик | `APPLY_LIVE=0` + сетевой фильтр + `act()`; n8n отлажен на фейке; первые живые — под присмотром |
| Двойной отклик | атомарные Update с условием; «уже откликались» перед кликом; кэш последнего результата |
| Обрыв посреди отклика | robot доделывает действие сам; зависший `applying` → очередь через 6 мин; `--applier` ждёт простоя |
| Потеря сессии | бэкап и восстановление `storageState`; тревога; очередь ждёт |
| hh поменял вёрстку или A/B-тест | данные — из XHR и InitialState, действия — по `data-qa` из одного файла; скриншот при сбое; повторная разведка / запись |
| Личные данные | сессия и журналы — в томе; разведка — в `fixtures/` (не в git); тексты HR не хранятся; VNC с паролем и только на 127.0.0.1 |

## Рассмотренные альтернативы

| Вариант | Почему нет |
|---|---|
| Повтор запроса отклика с cookies (§4 B) | xsrf, протухание сессии, легче заметить; интерфейс hh сам формирует запросы |
| Расширение в Chrome пользователя | нужен открытый Chrome, мешает работе; пользователь выбрал Docker |
| Очередь внутри робота | два источника правды; в v1 оркестрирует n8n через таблицу |
| Автоотклик по решению нейросети | 42% совпадения; решает пользователь кнопкой |
| Новые статусы `queued` / `applying` | колонка `apply_state`: не трогаем вкладки, карточки и всё, что фильтрует по статусу |
| VPS | домашний IP — главный актив |
| Официальный «автоотклик» hh | hh сам выбирает вакансии — не отклик на ✅ с нашим письмом |

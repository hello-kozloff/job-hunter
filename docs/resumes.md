# Несколько резюме (16.10.2026)

Человек заводит несколько резюме **в приложении** (разные профессии или ставки) и может импортировать их с hh. У каждого резюме свой поиск, оценка и письма. Решения пользователя — 16.10.2026.

## Что общее, что своё

- **Общее** на всю установку: подпись, контакт, часовой пояс, провайдер нейросети, фильтры (стоп-слова, чёрный список, пороги), пресет `profile.preset`.
- **Своё** у каждого резюме: текст (`resume`), «Дополнительно» (`extra`), факты (`facts`), строки «О кандидате» (`about`), правила и случаи оценки (`rules`, `cases`), роли, слова, форматы, город и образование для поиска (`roles`, `in_name`, `anywhere`, `formats`, `area`, `education`).

## Данные

Основное резюме `r1` — прежние глобальные ключи `settings` (`profile.*`, `llm.*`, `search.*`): миграции нет, промпты владельца и `prompt_v` не меняются. Остальные (r2–r5) — один ключ `resume.<id>` с теми же полями (список полей — `RESUME_FIELDS` в `n8n/shared/settings.js`).

- `resumes` — список `{ id, name, active, hh: {hash, title} | null }`, до 5, `r1` обязателен. Пока не сохранён — одно основное (`resumeList`).
- `resume.r2` … `resume.r5` — данные резюме или `null`. Поля, которых нет, берутся по умолчанию ключа.
- `vacancies.resume_id` — чьим поиском найдена вакансия, пусто — `r1`. Удалённое или неизвестное резюме — как `r1`.

## Код

`n8n/shared/resumes.js` (подключается после `settings.js`):

| Функция | Что |
|---|---|
| `resumeList(s)`, `resumeById`, `activeResumes` | список резюме |
| `nextResumeId(s)` | свободный id r2–r5 или `null` |
| `resumeSettings(s, id)` | настройки резюме: `r1`/неизвестное — сами `s`, иначе копия с подменой полей |
| `resumeData(s)` | поля резюме из настроек (клонирование) |
| `resumeRows(s, id, patch)` | что записать в `settings` при правке полей |

W1, W2 и W5 берут `resumeSettings(s, resume_id)` и дальше работают как раньше: у одного резюме результат тот же.

Тесты: `node --test scripts/test-shared.mjs`.

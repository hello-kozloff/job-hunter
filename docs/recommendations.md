## Принципы

1. **Одно резюме — одна правда.** `profile.resume` + `profile.extra` в `settings`. W2 и W5 читают их через `resumeText(s)` (`n8n/shared/settings.js`) — правка сразу работает в оценке и письмах. `prompt_v` теневого режима не меняется: хеш берётся до резюме.
2. **Нейросеть предлагает, код применяет.** Правка = `{ where, old, new, why }`. Код ищет `old` в тексте дословно и ровно один раз, сам решает, добавление это или замена, применяет к черновику. Резюме целиком нейросеть не переписывает.
3. **Без клика ничего не меняется.** Каждая правка — кнопкой. В `settings` пишем только в конце сессии; если резюме успело поменяться (новый PDF в W11) — не пишем.
4. **Факты — только от человека.** В правки идёт только то, что есть в резюме, просьбе или ответах. Личные данные (имя, контакты, город, переезд, гражданство, зарплата, формат, даты, компании и должности) нейросеть не меняет, если человек прямо не просит.
5. **Свои проекты — отдельно от опыта работы.** То, что человек делал в пет-проектах или на фрилансе, идёт только в строку про них или в «Дополнительно» — не в общий список навыков и не в опыт компаний. Иначе W5 решит, что это коммерческий опыт (`PET_LINE` в `n8n/w5-letter/build-letter.js`), и напишет так в письме. На hh такие навыки попадут в ключевые навыки при экспорте.

```
    нет в резюме: Vue.js · Angular · AWS · React Native · Go
[🔍 Анализ резюме] [⬆️ Upgrade резюме]
[📄 Резюме файлом] [↩️ Откатить]
[⬅️ Настройки]
```

Пока `profile.ready = false` — «📄 Сначала пришли резюме PDF».

**Upgrade:**
1. ⬆️ → вопрос ForceReply «⬆️ Резюме — что добавить или поменять?» → ответ.
2. «⏳ Ищу в резюме, куда это вписать…» → план:
   ```
   Просьба: «Добавь в стек PHP и скажи, что работал с ним в Руб Икс: делал админку»
   Понял так: …
   Куда впишу
   1. Опыт: Руб Икс — ➕ допишу, что делал админку на PHP
   2. Навыки — ➕ добавлю PHP в список навыков
   [✅ Верно] [✏️ Не так] / [❌ Отмена]
   ```
   - ➕ — только допишу, ✏️ — старый текст придётся убрать или переписать.
   - «✏️ Не так» — ответом, план пересобирается.
   - Не хватает данных (где был опыт, что делал) — до 2 вопросов кнопками. Тогда мест в плане может не быть: «куда впишу — решу после ответа».
3. После «✅ Верно» план остаётся в чате без кнопок (урок 14.10.2026 из онбординга: затёртую сводку не видели), вопросы и правки идут новой панелью.
4. Вопрос: варианты кнопками + [✍️ Свой ответ] [⏭ Пропустить] [⏹ Хватит]. «⏹ Хватит» — правки по тем ответам, что уже есть.
5. Правки по одной:
   ```
   ✏️ Правка 1/2 · Опыт: Руб Икс
   … сложные пользовательские сценарии<s>.</s> <b>и делал админку на PHP.</b>    ← пословный дифф с контекстом
   Почему: просьба добавить PHP
   добавление:  [✅ Применить] [✏️ Иначе] [⏭ Не надо]
   замена:      ⚠️ Правка убирает старый текст. Заменить?
                [🔁 Заменить] [➕ Не заменять, дописать] / [✏️ Иначе] [⏭ Не надо]
   ```
   - «➕ Не заменять, дописать» — правка заново с пожеланием «ничего не убирай, только допиши». Если всё равно вышла замена — показывается снова с ⚠️.
   - «✏️ Иначе» — ответом пожелание, нейросеть переделывает эту правку.
6. Итог: «✅ Резюме обновлено: 2 из 2 правок · 🎯 89% → 91% · новое резюме уже работает в оценке и письмах» → [📄 Резюме файлом] [↩️ Откатить] [⬅️ Рекомендации].

**↩️ Откатить** — подтверждение «вернуть резюме, каким оно было до правки 15.10 15:01 (Upgrade: «…»)?». Откат меняет местами текущую версию и последнюю из истории: ничего не теряется, второй откат возвращает правку.

**📄 Резюме файлом** — `resume.md` целиком (резюме и «Дополнительно»): сообщение Telegram — до 4 096 знаков, резюме — до 30 000.

## Как устроено

**W13 Resume** — `jobHunterW13Resu`, код `n8n/w13-resume/*.js`, вызывает W3. Номер 13: W10 занят под Inbox, W12 — под вход в hh через бота. Отдельно от W11: тот держит онбординг, новая логика его не трогает.

```
Called by W3 | Manual → Job → Answer? → Answer (убрать «часики»)
Job → Settings → Plan → Rows? → Vacancies → Rows count → Route
  llm  → Wait («⏳ …» на панели) → Build → Claude? → Claude | Gemini → Parse → Step
  file → Resume file → To file (Convert to File, resume.md) → Send file
  step → Step
Step → Save? → Save rows → Save resume (upsert settings)
     → Freeze? → Freeze (план без кнопок) → Render → Layout → New: | Edit: <раскладка> → Remember (panelId)
     → Prompt? → Prompt (ForceReply) → Delete ids → Delete (вопрос и ответ человека)
```

- **Job** разбирает callback_data сам: W3 только передаёт кнопки `rs: ru: rq: rp: rr:` и ответы на `RESUME_PROMPTS`.
- **Plan** — переходы по кнопкам и ответам человека: записать ответ, применить или пропустить правку, решить, нужна ли нейросеть (`route: llm`, `mode: plan | patch | rework`) и строки вакансий (`rows` — покрытие навыков на панели и в итоге).
- **Build / Parse** — запрос и проверка ответа (`n8n/shared/llm.js`).
- **Step** — ответ нейросети в сессию, экран, сохранение, вопрос ForceReply.
- **Хранение запусков:** успешные не храним (`saveDataSuccessExecution: none`, как у W7): панель и анализ читают всю таблицу вакансий. Ошибки сохраняются и идут в W4.

**Сессия** — static data `session`, одна за раз. `sid` (4 знака) — в callback_data: кнопки прошлой сессии отвечают «⌛ устарели». Поля:
- `kind` (upgrade | analyze), `base` — отпечаток резюме на старте, `original` и `draft` — `{ resume, extra }`;
- `report`, `started` — отчёт анализа и «▶️ Начать»; `done` — итог без правок (ответы только на подсказки);
- `instruction`, `notes` (что «не так» в плане), `plan`, `planOk`, `planMsg`, `planText`, `moved` — вопросы и правки уже на новой панели;
- `questions`, `qi`, `answers`, `picks` — галочки текущего вопроса;
- `patches`, `pi`, `dropped`, `applied`;
- `last` — последний запрос к нейросети для «🔄 Повторить» (429, сеть).

**`resume.history`** (`n8n/shared/settings.js`) — до 5 прежних версий `{ at, by: upgrade | analyze | undo, note, resume, extra }`, новые сверху. Пишет только W13. Лежит в `settings`, а не в static data: так надёжнее, и она попадает в бэкап `profile-export`.

**callback_data:**

| Данные | Что |
|---|---|
| `rs:view` · `rs:an` · `rs:up` · `rs:file` · `rs:undo` · `rs:undo:y` | панель, анализ, Upgrade, файл, откат (вопрос / да) |
| `ru:<sid>:<y\|e\|n>` | план Upgrade: верно, не так, отмена |
| `rq:<sid>:<вопрос>:<0-7\|t\|k\|d>` · `rq:<sid>:x` · `rq:<sid>:go` | вариант или галочка, свой ответ, пропустить, готово (галочки); хватит; начать (анализ) |
| `rp:<sid>:<правка>:<y\|r\|a\|e\|n>` | применить, заменить, дописать, иначе, не надо |
| `rr:<sid>` | повторить запрос к нейросети |

**Вопросы ForceReply** (`RESUME_PROMPTS`, `n8n/shared/menu.js`): `upgrade`, `answer`, `plan`, `patch`. W3 узнаёт ответ по началу текста вопроса.

**Раскладки** (`RESUME_LAYOUTS` в `scripts/build-workflows.mjs`, порядок = `n8n/w13-resume/render.js`):
- `rs root`, `ru plan`;
- `rq one2` / `rq one3` / `rq one4` — варианты по одному в ряд, подписи длинные;
- `rq many8` — галочки по две в ряд, пустые места — «·» (`p:x`);
- `rq text` — без вариантов;
- `rp add`, `rp replace`, `rs done`, `rs undo`, `rs back`, `rs retry`, `rs report` (отчёт анализа).

Число кнопок Telegram-ноды задаётся при сборке (`docs/bot-menu.md` → ограничения), поэтому раскладки фиксированные.

### Нейросеть

Модель — как у разбора резюме W11 (`llmModel`): `GEMINI_PROFILE_MODEL`, иначе `GEMINI_MODEL`; Claude — если в ⚙️ → 🤖 выбран Claude. В тексте промптов нет ни одного тире: Flash-Lite копирует типографику промпта (§7 CLAUDE.md, письма).

| Режим | Ответ (JSON-схема) | Проверка кодом (`n8n/w13-resume/parse.js`) |
|---|---|---|
| `analyze` | `summary[2–4]`, `questions[≤6 или 8]`: area (title · skills · experience · about · filters), problem, question, options, tip | первым — вопрос кода про навыки; filters → подсказка с кнопками «Поменяю / Оставлю»; всего ≤ 8 |
| `plan` | `understood`, `places[≤5]`: where, action add/replace, what; `questions[≤2]`: question, options | места или вопрос — хотя бы что-то; вопрос с вариантами 2–4 (до 40 знаков), иначе — свой ответ |
| `patch` | `patches[≤8]`: where, old, new, why | `checkPatches` (ниже) |
| `rework` | одна правка | тот же |

Температура: план — 0, правки — 0,2, «иначе» — 0,5.

### Правки (`n8n/shared/resume.js`)

- **Текст** — как `resumeText`: резюме, `\n\n## Дополнительно\n`, extra. Правка внутри резюме меняет `profile.resume`, внутри extra — `profile.extra`, на стыке — отбрасывается.
- **Поиск `old`:**
  - точное совпадение;
  - нет — без учёта пробелов, кавычек, тире, «ё» и маркеров списка, с переводом позиций обратно в исходник.
  - Не нашлось или нашлось дважды — правка отбрасывается, на первой правке — «ещё N не смог привязать к тексту».
- **Добавление или замена** — решает код: все слова `old` по порядку остались в `new` (без регистра и знаков по краям) → добавление, иначе замена.
- **Пустой `old`** и место «Дополнительно» — новая строка в конец `profile.extra`. Это для человека, который «Дополнительно» ещё не заполнял: свои проекты больше некуда вписать.
- **Применение** — по очереди к черновику, `old` ищется заново: прошлая правка могла его поменять. Пределы — `profile.resume` ≤ 30 000, `profile.extra` ≤ 4 000, правка ≤ 1 500.
- **Дифф** — пословный (LCS): `<s>убрал</s> <b>добавил</b>`, длинные куски без изменений — «…» с 8 словами контекста.

### Покрытие навыков (`skillStats`)

- **Вакансии:**
  - целевые — `my_decision` ∈ apply, maybe, earlier или решения нет, а нейросеть сказала apply;
  - таких с навыками меньше 10 — все, что прошли фильтр.
- **Навыки** — `key_skills`; одинаковые сводит `skillKey`: React.js = ReactJS = React, HTML5 = HTML, postgres = PostgreSQL.
- **Есть в резюме** — названия навыка из `skillVariants` (`n8n/shared/skills.js`, как у W5), с номером версии после: «HTML» есть в «HTML5/CSS3».
- **Покрытие** — по 30 самым частым навыкам: сумма частот тех, что есть в резюме, к сумме всех.

## Разделы резюме (часть D, S1–S4)

Решения владельца 15.10.2026, после E0: на hh опыт работы хранится в профиле и общий для всех резюме. Поэтому в боте:
- **«💼 Опыт работы» — отдельный раздел, общий для всех резюме.** Его дорабатывает нейросеть; на каждой его правке — «⚠️ общий раздел»;
- несколько резюме — **заложены** (`cv.resumes[]`), пока одно и оно связано с резюме на hh;
- разделы в первый раз — **с hh (робот) и из текста бота**, по каждому разделу человек выбирает «бот / hh»; без робота — только раскладка текста;
- **30 ключевых навыков hh** выбирает человек: галочки по 8 на странице, счётчик N/30, частота в вакансиях.

**Разметка поверх текста** (`n8n/shared/cv.js`, настройка `cv`):
- текст резюме остаётся как есть; разделы — именованные куски. `cv.resumes[i].template` — текст с метками `⟦title⟧`, `⟦about⟧`, `⟦p:e1⟧` (должность места), `⟦d:e1⟧` (описание места);
- `cvRender(cv) === profile.resume` — разметка живая (`cvFresh`). Текст переписал кто-то другой (новый PDF в W11, импорт) — разметка устарела: W13 работает с текстом, как без неё, и предлагает разложить заново. W2, W5, W11 не меняются;
- компания и даты места остаются в тексте вокруг меток и не правятся;
- `keySkills` — только для hh, в текст не попадают: навык из пет-проекта в общем списке W5 счёл бы коммерческим;
- **раскладка**: нейросеть (режим `split`) даёт якоря — начало и конец кусков, должность и компанию дословно; код режет текст (`cvFromAnchors`). Якоря ищутся по порядку, первое вхождение в своём куске: должность места — после компании, иначе ближайшая перед ней. Не нашлось — раздел остаётся текстом с пометкой. Раскладка без потерь (`render === text`) или её нет;
- **правки**: раздел правки — по позиции в тексте (`cvPartAt`): `title`, `about`, `p:e1`, `d:e1`, `text` (вне разделов), `extra`. Правка через границу разделов или по метке (компания + должность) — «задевает два раздела». У Upgrade из «💼» только правки опыта (`scope: experience`);
- `resume.history` хранит и разметку; откат возвращает её вместе с текстом. Версия без разметки разметку не трогает: та станет неживой и оживёт при откате обратно.

**Чтение hh роботом** (S2, `applier/src/flows/resume.mjs`, `POST /resume/read {hash?}`, CLI `node scripts/applier.mjs cv`):
- «Мои резюме» → страница резюме (по умолчанию — видимое работодателям, иначе первое) → `applicantResume` из InitialState → `{ resumes, resume: { hash, title, about, keySkills, places[{ hhId, company, position, description, start, end }], access, status, updated, limits } }` (`parseResume`, `applier/src/hh/resume.mjs`);
- только GET, строгий предохранитель; замок `resume-read` (занят откликом — 409, блок — 423); капча — блок, как у отклика; не вошли — `{ ok: false, error: 'login' }`;
- бэкап прочитанного резюме целиком — `/data/resume/<hash>-<время>.json`, 30 дней;
- фейк (`APPLIER_FAKE=1`) отдаёт синтетическое резюме;
- предохранитель теперь рвёт и не-GET к `resume-profile-front.hh.ru` (сохранение опыта, урок E0); действия `resume` (`hh.ru/applicant/resume/edit`) и `profile` (сохранение опыта) экспорт откроет по одному.

**В боте** (S3–S4, W13):
- панель 💡 показывает разделы: должность (и связано ли с hh), сколько мест работы, ключевых навыков N/30; кнопки [💼 Опыт работы] [🧰 Навыки hh];
- 💼 или 🧰 без живой разметки → 🧩 раскладка: «⏳ Читаю резюме на hh и раскладываю…» — ветка W13 `Wait hh` → `Read hh` (робот) → `Hh` → раскладка нейросетью (`split`) → сверка. Робота нет (нет связи) — сразу без hh; занят, капча, блок, не вошёл — экран причины [🔄 Повторить] [➡️ Без hh] [❌ Отмена];
- **сверка** — только разделы, которые на hh другие, по одному: пословный дифф «бот → hh», [🤖 Оставить как в боте] [🌐 Взять с hh]; на разделах опыта — «⚠️ общий для всех резюме»; место только на hh — [➕ Добавить в бота] [⏭]; места сопоставляются по компании (без ООО/АО) и году начала;
- **🧰 навыки hh** — 8 галочек на страницу, [◀️] [✅ Готово · N/30] [▶️]; отмечены те, что на hh (без hh — самые частые в вакансиях); больше 30 — «сначала сними другой»; в текст бота не попадают;
- **💼 Опыт работы** — места (компания, должность, период, длина, 🔗 hh) и [⬆️ Улучшить опыт]: Upgrade с `scope: experience` — в промпте «правь только опыт работы», правки вне опыта код отбрасывает;
- на любой правке опыта (анализ, Upgrade) — название раздела и «⚠️ Опыт работы — общий раздел»;
- итог раскладки: что взято с hh, что добавлено, что не разложилось (осталось текстом); текст поменялся — версия в `resume.history` (↩️).

**Проверка S3–S4 (15.10.2026):**

### E0: разведка и запись (15.10.2026)

Решение владельца: правки для записи — **на скрытой копии резюме**, основное резюме на hh не трогаем.

1. **Разведка без кликов** — робот сам, `node scripts/applier.mjs recon --resume`:
   - открывает «Мои резюме», страницу каждого резюме (до 3) и страницы правки по ссылкам с неё (до 8);
   - ссылки-действия (удалить, поднять в поиске, скрыть, копия, скачать) не открывает никогда (`applier/src/hh/resume.mjs` → `editLinks`);
   - **строгий предохранитель**: на время разведки рвётся любой не-GET к hh, не только к `/applicant/` (как hh сохраняет резюме, ещё неизвестно); что страницы пытались отправить сами — в `blocked.json`;
   - каждая страница — `page.html`, `state.json` (без токенов), `dom.json` (поля форм: имя, `data-qa`, `maxlength`, длина значения — без самих значений), скриншот во всю страницу. Это же бэкап резюме hh до первой правки. Папка — `fixtures/applier/resume-…` (не в git).
2. **Запись** — владелец в окне робота («Общий экран», `vnc://localhost:5901`), `node scripts/applier.mjs record start`:
   - «Дублировать» резюме → копию скрыть («Не видно никому»);
   - в копии поменять и сохранить: должность, ключевой навык (добавить и убрать), «О себе», одно место опыта (должность и описание);
   - удалить копию → `record stop`;
   - русский текст — `node scripts/applier.mjs paste` (буфер обмена Mac → туда, где курсор: VNC передаёт только латиницу) или латиницей: содержимое копии не важно.
   Запись пишет любой не-GET к hh и GET с `resume` в адресе (`recordWanted`), предохранитель на время записи выключен, отклики W9 ждут (замок).

#### Итог E0 (15.10.2026)

Разведка `fixtures/applier/resume-20261015-140015` (до записи — бэкап резюме hh), запись `record-20261015-140926` (первая попытка `record-20261015-140227` оборвалась: подвисло окно «Общего экрана», сам браузер робота отвечал).

**Чтение — без форм.** Резюме целиком — в InitialState страницы `/resume/<hash>` → `applicantResume`:
- `title[0].string` — должность; `skills[0].string` — «О себе»; `keySkills[].string` — ключевые навыки (`advancedKeySkills` — с id);

| Поле | Предел hh (`_conditions`) |
|---|---|

| Опыт: `position` / `description` | до 512 / до 32 768 |

**Запись — по частям**, формы открываются прямым адресом (без клика по карандашу на странице резюме):

| Что | Страница формы | `data-qa` | Запрос сохранения |
|---|---|---|---|
| Должность (+ зарплата, формат, занятость — уходят вместе) | `/resume/edit/<hash>/position` | `resume-edit-title-suggest`, `resume-partial-edit-save` | `POST hh.ru/applicant/resume/edit?resume=<hash>&hhtmSource=resume_partial_edit` → `{ title, salary, workFormats, employmentForms, professionalRole, travelTime, businessTripReadiness }` |

- Ответ `applicant/resume/edit` — резюме целиком (`{ resume: { _attributes, … } }`): по нему сверка без лишнего чтения. Ответ профиля — пустой, 200.
- В теле — отпечатки браузера `fingerprintIteration2`, `fingerprintSp` (считает скрипт hh). Поэтому робот **заполняет форму и жмёт «Сохранить»**, как человек; запросов сам не собирает.
- Подсказки (`POST /shards/recommended_skills`, `profession_suggestions`) — не сохранение.

**Уроки:**
1. **Опыт работы — в профиле, общий для резюме.** Правка места работы в скрытой копии ушла и в основное резюме (видно работодателям) и после удаления копии осталась: «Senior Frontend Developer TEST» около 3 минут, 15.10.2026 14:11–14:15 UTC. Владелец вернул руками, сверка разведкой — совпадает с бэкапом до записи. На странице правки опыта — галочки «в каких резюме показывать» (`profile-resumes-list-checkbox-<hash>`). Экспорт опыта меняет все резюме, где место отмечено, — W13 должен это говорить.
2. **Предохранитель робота не покрывает профиль.** `GUARD_URL` рвёт не-GET к `hh.ru/applicant/…` (сохранение резюме), но не к `resume-profile-front.hh.ru` (сохранение опыта). До сухих прогонов (E2) — добавить; сохранение резюме и опыта — отдельные действия `guardAllow`.
3. Копию резюме для опытов больше не делаем: она не изолирует опыт. Сухой прогон E2 — заполнить форму и не сохранять (предохранитель рвёт), живой — на основном резюме с бэкапом.

**Как W13 будет выгружать:**
1. Робот читает резюме hh.
2. Нейросеть раскладывает текст бота по полям hh (режим `map`).
3. Код проверяет дословность: каждая строка поля — из резюме бота.
4. Сравнение с `resume.hh_sync` (поля hh после прошлой выгрузки):
   - **на hh** — бот поменялся, hh нет;
   - **в бота** — hh поменяли руками, бот нет;
   - **спор** — поменялись оба или выгрузки ещё не было.
5. Поля по одному: [➡️ На hh] [⬅️ Забрать в бота] [⏭ Не трогать].
6. [🧪 Сухой прогон] / [✅ Записать на hh].
7. Запись, сверка чтением.

# Меню бота: «📋 Вакансии» и «📊 Статистика»

**Цель:** под полем ввода в Telegram — постоянные кнопки. По ним видна база вакансий (последние сверху, с вкладками и страницами) и статистика: когда был сбор, когда следующий, сколько вакансий рассмотрено.

Решения пользователя (07.10.2026):

| Вопрос | Решение |
|---|---|
| Список | Вкладки по статусу с числом на каждой, по 8 вакансий на странице, новые сверху |
| Открыть вакансию | Карточка в панели с кнопками решения. Решение правит и исходную карточку в ленте, «Почему?» и письмо работают как обычно |
| Чат | Одна живая панель: нажатие и прошлая панель удаляются, листание правит панель на месте |
| Поиск | Не нужен |

## Как пользоваться

- **Кнопки под полем ввода** — `[📋 Вакансии] [📊 Статистика]` и `[⚙️ Настройки]` (с 07.10.2026). Они появляются после `/start`. Если клавиатура свернулась, её возвращает значок клавиатуры в поле ввода или `/start`.
- **Вопрос «Почему?»** приходит в режиме ответа (force reply), и Telegram на это время прячет кнопки меню. Вернуть их может только новое сообщение бота с клавиатурой. Поэтому клавиатура приходит вместе с «✍️ Записал причину», сообщением о сборе и итогом после карточек (W2), утренней сводкой (W6) и приветствием. Не стал отвечать на «Почему?» — `/menu` вернёт кнопки сразу.
- **Команды:**
  - `/vacancies` — список;
  - `/stats` — статистика;
  - `/settings` — настройки;
  - `/menu` и `/start` — приветствие с кнопками.

**Список:**

```
📋 Вакансии · ⏳ Ждут решения — 9 · стр. 1/2

1. 🟡⏳ Senior Fullstack-разработчик (Python + React, Nodejs)   ← ссылка на hh
   Плавно · 💰 от 250k ₽ до налогов · 13 ч назад · /v147     ← /v147 — открыть в панели
…
[• ⏳ 9] [✅ 7] [📨 3]
[❌ 2]  [🚫 20] [📋 41]
[ · ]   [1/2]   [▶️]       «·» — некуда листать; номер страницы — обновить её
```

| Вкладка | Статусы строк |
|---|---|
| ⏳ Ждут решения | `waiting` |
| ✅ Откликнусь и 🤔 | `approved`, `maybe` |
| 📨 Отправлено | `applied` (свежие отклики сверху) |
| ❌ Мимо и устаревшие | `skipped`, `expired`, `archived` |
| 🚫 Отсеяно фильтром | `rejected` (первая причина — в строке) |
| 📋 Все | всё, кроме бэкфилла `seen` |

- Открывается на ⏳, если там что-то есть, иначе на 📋.
- Значки в строке: вердикт нейросети (🟢 🟡 🔴 ⚠️) и статус (⏳ ✅ 🤔 ❌ 📨 ⌛ 🔒 🚫, ⚙️ — ждёт нейросети).

**Карточка в панели (`/v169`):** текст как у карточки в ленте. Кнопки зависят от статуса:

| Статус | Кнопки |
|---|---|
| ждёт решения (есть карточка в ленте) | `[✅ Откликнусь] [🤔 Возможно] [❌ Мимо]` / `[📨 Уже откликался] [🚫 В ЧС]` / `[🔗 На hh] [⬅️ К списку]` |
| решение принято, «📨 откликался раньше» | `[↩️ Изменить] [🔗 На hh]` / `[⬅️ К списку]` |
| отсеяна фильтром (08.10.2026) | `[✅ Откликнусь] [🤔 Возможно] [📨 Уже откликался]` / `[🤖 На оценку]` / `[🔗 На hh] [⬅️ К списку]` |
| отправлено, устарела, закрыта, без карточки | `[🔗 На hh] [⬅️ К списку]` |

«⬅️ К списку» возвращает на вкладку и страницу, с которой открыли.

**Отсеянная фильтром** (решение пользователя 08.10.2026: фильтр ошибается, вакансию надо уметь вернуть):
- описания нет (фильтр отсёк по выдаче) — перед ✅ / 🤔 / 🤖 W3 загружает страницу с hh (`Rescue page` → `Rescue parse` → `Save page`); не открылась — решение всё равно принимается, письмо и оценка пойдут по фрагменту; вакансия закрыта — «🔒 закрыта», решения нет. Правила фильтра по странице второй раз не применяются;
- ✅ / 🤔 / 📨 — решение записывается, в ленту уходит карточка со строкой «🧹 Отсеяна фильтром: …» и «↩️ Изменить» (`Card: new` → `Save card`: `tg_message_id`, `card_at`); на неё отвечает «Почему?» с причинами фильтра (ответ → `my_reason`, по ним правим фильтр; у 📨 не спрашиваем) и письмо (✅);
- 🤖 На оценку — `status = detailed`, W3 сразу запускает W2 (`Score now`), карточку с решением нейросети пришлёт он;
- в теневой режим такие решения не идут: у нейросети нет оценки (кроме 🤖).

После «📨 Отправил» / «↩️ Отменить» / «↩️ Отменить отклик» под письмом W3 обновляет панель, если на ней открыта эта вакансия (`Sync job` → W7, вид `sync`): отправлен — без кнопок решения, отменён — снова «↩️ Изменить», отклик отменён (14.10.2026, вакансия снова ждёт решения) — кнопки выбора. Под отправленным письмом — «📋 К вакансиям»: новая панель внизу со списком на прежней вкладке.

**Статистика:**
- **Сбор:**
  - последний сбор: время по местному (в скобках — МСК), результат и сколько новых вакансий он нашёл;
  - следующий сбор по расписанию;
  - сколько сборов прошло за сутки из положенных.
- **Вакансии:**
  - найдено (без бэкфилла);
  - отсеяно фильтром;
  - ждут нейросети;
  - оценки нейросети.
- **Рассмотрено тобой:** сколько карточек с решением из всех отправленных карточек; ждут решения и сколько ждёт самая старая; ✅ 🤔 ❌ 📨 ⌛ 🔒.
- **Теневой режим:** N/50 и доля совпадений.
- **Кнопки:** `[🔄 Обновить] [⏳ Ждут решения · N]`.

- После нажатия панель показывает новое значение и «✅ Записал». Если менялось расписание — ещё и обновился ли страж healthchecks.
- «✏️» — бот присылает вопрос, ответ на него — новый список через запятую. Вопрос и ответ потом удаляются, панель показывает новый список (или ошибку — тогда «✏️» ещё раз).
- «⚙️ Правила» — 10 кнопок ✅ / ◻️: выключенное правило не отсекает, такие вакансии дойдут до нейросети.
- «🚫 Чёрный список» — компании с командами `/bl<id>`: команда спрашивает «Убрать?». Добавить — кнопкой «🚫 В ЧС» на карточке вакансии.

## Как устроено

```
W3 Telegram  Route → Panel? ─ да → Menu (Execute Workflow W7, без ожидания)
                            └ нет → Button? → … (кнопки карточек и писем, ответы — как раньше)
             pv:… (решение в карточке на панели) → Vacancy → Apply choice → Save choice → Answer
                → Decided? → исходная карточка в ленте (row.tg_message_id), «Почему?», письмо
                → From panel? → Panel job → Panel refresh (W7: перерисовать панель)

W7 Bot menu  Called by W3 | Manual → Manual job (приветствие)
             → Job → Answer? → Answer query (убрать «часики»)
             → Work? (p:x — дальше не идём) → Settings (таблица settings)
                → Setting change → Save setting (upsert) → HC plan → HC sync (API healthchecks)   ⚙️ «▸»
                → Collect now → Run W1                                                          «🔄 Собрать сейчас»
                → Rows (вся таблица) → Runs (журнал сборов, 100 последних)
             → Render → Layout (Switch по $json.route) → New: <раскладка> | Edit: <раскладка> → Remember
                      → Delete ids → Delete old (нажатие пользователя и прошлая панель)
```

- **Код:**
  - `n8n/w7-menu/*.js`;
  - `n8n/w3-telegram/{route,apply-choice,panel-job}.js`;
  - общий код — `n8n/shared/menu.js` (подписи, вкладки, значки) и `n8n/shared/schedule.js` (расписание W1, его же использует сводка W6).
- **callback_data** (не длиннее 64 байт):
  - `p:l:<tab>:<page>` — список;
  - `p:s` — статистика;
  - `p:x` — неактивная кнопка;
  - `p:n` — новая панель со списком там, где был (кнопка «📋 К вакансиям» под отправленным письмом);

## Ограничения n8n 2.42.3 (проверено по исходникам)

- **Число inline-кнопок у Telegram-ноды задаётся при сборке.** Выражениями меняются только подписи и callback_data. Поэтому:
  - раскладки фиксированные: 5 раскладок × «новое сообщение / правка» плюс приветствие;
  - вакансия открывается командой `/v<id>` в тексте, а не кнопками с номерами.
- **`is_persistent` и `input_field_placeholder` нода отбрасывает:** `getNodeParameters` удаляет неизвестные ключи collection. Клавиатура остаётся, но пользователь может её свернуть.
- **HTTP Request к Bot API не используем:** токен бота пришлось бы положить в `$env`.
- **Data Table Get не умеет пропускать строки (skip).** Поэтому W7 берёт всю таблицу и считает в коде. 07.10.2026 это 132 строки, 350 КБ. Если строк станет больше ~3000, список надо перевести на публичный API `GET /api/v1/data-tables/{id}/rows`: там есть `limit` и `cursor` = base64 `{offset, limit}`, `filter`, `sortBy`. Ключу API тогда понадобится право `dataTableRow:read`.

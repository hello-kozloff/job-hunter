# Настройки из бота (⚙️)

**Цель:** часть настроек системы меняется кнопками в Telegram, без правки кода и деплоя.

Решения пользователя (07.10.2026):
- в первой версии — разделы «Сбор», «Поиск и фильтр», «Нейросеть»; «Уведомления» — вторым шагом;
- страж healthchecks.io при смене расписания обновляется через свой API.

## Как устроено

- **Хранилище** — таблица `settings` (`name`, `value_json`). В ней только то, что пользователь поменял. Пустая таблица — значения по умолчанию, то есть поведение до появления настроек. Деплой таблицу не трогает.
- **Схема** — `n8n/shared/settings.js`:
  - `SETTINGS` — имя, значение по умолчанию, допустимые значения;
  - `loadSettings($('Settings').all())` — значения с учётом таблицы; значение не из списка заменяется значением по умолчанию;
  - `nextSetting(name, value)` — следующее значение по кругу (кнопка «▸»);
  - `scheduleFrom(settings)` — расписание для `n8n/shared/schedule.js`.
- **Чтение** — нода «Settings» (Data Table Get, все строки, один раз за запуск) в W1, W6, W7, W8; хелпер `settingsNode` в `scripts/build-workflows.mjs`.
- **Запись** — только W7: «Setting change» (следующее значение) → «Save setting» (upsert по `name`). Панель после нажатия показывает новое значение.

## Настройки

| Имя | По умолчанию | Значения | Кто читает |
|---|---|---|---|
| `collect.day_every` | 30 | 15 · 30 · 60 мин | W8 Clock, W1 (следующий сбор), W6, W7 |
| `collect.night_every` | 120 | 60 · 120 · 240 мин · 0 (ночью не собирать) | то же |
| `collect.day_window` | `07-18` | `07-18` · `08-20` · `06-22` · `09-18` (часы МСК) | то же |
| `collect.paused` | false | false · true | то же; пауза ставит на паузу и стража |

Слоты выровнены по полуночи МСК, шаг сетки — 15 минут. По умолчанию получается 29 сборов в сутки: днём 07:00–17:30 каждые 30 мин, ночью 18, 20, 22, 00, 02, 04, 06.

## Расписание: «часы» W8 Clock

У Schedule Trigger cron зашит в workflow: прочитать его из таблицы нельзя, а переписывать workflow через API — это расхождение с git. Поэтому:

- **W8 Clock** тикает каждые 15 мин (`*/15 * * * *`, `misfirePolicy: coalesce`), цепочка: Settings → «Due» → W1 (без ожидания).
- **«Due»** (`n8n/w8-clock/due.js`) — сбор нужен, если с прошлой отправки (static data `dispatchedAt`) прошёл хотя бы один слот по настройкам:
  - `kind = schedule` — слот этого тика;
  - `kind = catchup` — пропущенный слот, Mac спал: после пробуждения один догоняющий сбор;
  - на паузе — ничего.
- **W1** своего расписания не имеет. Его запускают W8 и кнопка «🔄 Собрать сейчас» (`kind = bot`). Параллельный запуск отсекает журнал `runs`.
- **Успешные тики** W8 не хранятся (`saveDataSuccessExecution: none`). Сборы видны в журнале `runs`.

## Страж healthchecks.io

При смене `collect.*` W7 пересчитывает OnCalendar (`onCalendar(sch)` в `schedule.js`) и запас (интервал днём + 20 мин) и отправляет их стражу:
- `POST https://healthchecks.io/api/v3/checks/<uuid>`, uuid берётся из `HC_PING_URL`;
- пауза — `POST …/pause`. Следующий пинг после «▶️ Возобновить» снимет паузу сам.

Ключ — `HC_API_KEY` в `.env` → credential «healthchecks API» (`jobHunterHcApi01`, заголовок `X-Api-Key`, `scripts/credentials.mjs`). Без ключа настройки работают, а панель пишет «⚠️ Страж healthchecks не обновлён: нет ключа API».

**Разовое действие пользователя:**
1. healthchecks.io → проект → **Settings** → **API Access** → **Create API key** (read-write).
2. В `.env`: `HC_API_KEY=…`
3. `scripts/deploy.sh`.

## Как добавить настройку

1. `n8n/shared/settings.js`: строка в `SETTINGS` (`default`, `options`).
2. Код, который её читает: `loadSettings($('Settings').all())[имя]`, а в workflow — нода `settingsNode(...)`.
3. Кнопка в разделе панели W7 (`n8n/w7-menu/settings-view.js`, раскладка в `PANEL_LAYOUTS`), callback `sc:<имя>`.
4. Эта таблица и `docs/bot-menu.md`.
